# Lorebook And Regex Persistence Audit

Result: **bad**. I found likely persistence holes in module-level lorebook and regex/trigger editors. Global lorebook and global regex paths look normal in this slice.

## Findings

### 1. Module lorebook add/import can create UI-only entries with no command payload

`src/lib/Setting/Pages/Module/ModuleMenu.svelte` appends module lorebook entries without `id` fields in `addLorebook()` and `addLorebookFolder()` ([lines 100-132](../../../../../src/lib/Setting/Pages/Module/ModuleMenu.svelte#L100-L132)). Its module import path mutates `currentModule.lorebook` through the `lore` alias and never calls the module bridge or ID normalizer ([lines 155-177](../../../../../src/lib/Setting/Pages/Module/ModuleMenu.svelte#L155-L177)).

That matters because the module lorebook watcher only snapshots module lorebooks when every entry has a stable unique id ([`src/ts/server/lorebookBridge.svelte.ts` lines 1571-1573](../../../../../src/ts/server/lorebookBridge.svelte.ts#L1571-L1573), with the id check at [lines 1146-1149](../../../../../src/ts/server/lorebookBridge.svelte.ts#L1146-L1149)). After an ID-less entry is added, the changed collection is omitted from the snapshot map, so `watchServerBackedLorebooks()` has no key to dispatch ([lines 1355-1411](../../../../../src/ts/server/lorebookBridge.svelte.ts#L1355-L1411)).

The intended collection bridge does normalize IDs before command dispatch (`replaceModuleLorebookCollectionDraft()` calls `ensureClientLorebookEntryIds()` at [lines 554-570](../../../../../src/ts/server/lorebookBridge.svelte.ts#L554-L570)), but these add/import paths bypass it. If a later detail edit goes through `applyLorebookEntryDraftEdit()`, that can assign an id and persist; simply adding/importing and leaving the editor does not appear to send a payload.

Server behavior is strict and consistent: module lorebook replacement validates `entries` before mutation ([`server/fastify/src/routes/commands.ts` lines 5841-5849](../../../../../server/fastify/src/routes/commands.ts#L5841-L5849)), and command-path lorebook entries require a non-empty `id` ([`server/fastify/src/commands/lorebooks.ts` lines 321-327](../../../../../server/fastify/src/commands/lorebooks.ts#L321-L327)). The likely failure is therefore before server mutation: optimistic client state is not reflected in a command payload.

### 2. Module regex/trigger add/import/switch paths can also be UI-only

`ModuleMenu.svelte` appends module regex and trigger definitions without ids ([lines 179-202](../../../../../src/lib/Setting/Pages/Module/ModuleMenu.svelte#L179-L202)). Module regex import assigns the imported array back to `currentModule.regex`, but imported regex entries are not normalized for command ids ([lines 323-345](../../../../../src/lib/Setting/Pages/Module/ModuleMenu.svelte#L323-L345); `importRegex()` just pushes imported records at [`src/ts/process/scripts.ts` lines 79-101](../../../../../src/ts/process/scripts.ts#L79-L101)). Trigger UI paths also create ID-less definitions, including V1 add ([`src/lib/SideBars/Scripts/TriggerV1List.svelte` lines 93-103](../../../../../src/lib/SideBars/Scripts/TriggerV1List.svelte#L93-L103)) and trigger mode switches/default initialization ([`src/lib/SideBars/Scripts/TriggerList.svelte` lines 55-74](../../../../../src/lib/SideBars/Scripts/TriggerList.svelte#L55-L74), [lines 89-101](../../../../../src/lib/SideBars/Scripts/TriggerList.svelte#L89-L101); [`TriggerV2List.svelte` lines 350-360](../../../../../src/lib/SideBars/Scripts/TriggerV2List.svelte#L350-L360)).

The script-definition watcher only tracks module regex/trigger arrays when all definitions already have stable unique ids ([`src/ts/server/scriptDefinitionBridge.svelte.ts` lines 450-456](../../../../../src/ts/server/scriptDefinitionBridge.svelte.ts#L450-L456), checked at [lines 743-750](../../../../../src/ts/server/scriptDefinitionBridge.svelte.ts#L743-L750)). New ID-less definitions are therefore dropped from watched command generation rather than serialized.

The server command path requires ids too: script and trigger definitions reject missing ids ([`server/fastify/src/commands/scriptDefinitions.ts` lines 118-130](../../../../../server/fastify/src/commands/scriptDefinitions.ts#L118-L130)), and the module script/trigger routes validate before writing ([`server/fastify/src/routes/commands.ts` lines 6097-6104](../../../../../server/fastify/src/routes/commands.ts#L6097-L6104), [lines 6141-6148](../../../../../server/fastify/src/routes/commands.ts#L6141-L6148)). Again, the likely failure is client-side omission before payload construction.

Character script drafts do not share this specific bug: `CharConfig.svelte` applies drafts through `applyCharacterScriptDefinitionDraft()` ([lines 175-187](../../../../../src/lib/SideBars/CharConfig.svelte#L175-L187)), and that bridge normalizes script/trigger ids before dispatch ([`scriptDefinitionBridge.svelte.ts` lines 113-115](../../../../../src/ts/server/scriptDefinitionBridge.svelte.ts#L113-L115), [lines 164-176](../../../../../src/ts/server/scriptDefinitionBridge.svelte.ts#L164-L176)).

## Normal Paths Checked

- Global regex uses `createServerBackedSettingDraft('globalscript', ...)` ([`src/lib/Setting/Pages/GlobalRegex.svelte` lines 9-18](../../../../../src/lib/Setting/Pages/GlobalRegex.svelte#L9-L18)). The settings bridge optimistically writes `DBState.db[key]` and queues a settings patch ([`src/ts/server/settingsBridge.svelte.ts` lines 77-100](../../../../../src/ts/server/settingsBridge.svelte.ts#L77-L100)); command wrappers JSON-serialize the patch ([`src/ts/server/commands.ts` lines 2856-2874](../../../../../src/ts/server/commands.ts#L2856-L2874)); the server accepts `globalscript` as an array setting and writes settings ([`server/fastify/src/routes/commands.ts` lines 1229-1239](../../../../../server/fastify/src/routes/commands.ts#L1229-L1239), [lines 1319-1337](../../../../../server/fastify/src/routes/commands.ts#L1319-L1337)).
- Global lorebook settings delegate to `LoreBookSetting` ([`src/lib/Setting/Pages/GlobalLoreBookSettings.svelte` lines 14-22](../../../../../src/lib/Setting/Pages/GlobalLoreBookSettings.svelte#L14-L22)), which starts a global-scoped watcher ([`src/lib/SideBars/LoreBook/LoreBookSetting.svelte` lines 27-33](../../../../../src/lib/SideBars/LoreBook/LoreBookSetting.svelte#L27-L33)). The bridge normalizes global lorebook entry ids for collection dispatch ([`lorebookBridge.svelte.ts` lines 907-916](../../../../../src/ts/server/lorebookBridge.svelte.ts#L907-L916)) and command wrappers include entries in the request body ([`src/ts/server/commands.ts` lines 2156-2169](../../../../../src/ts/server/commands.ts#L2156-L2169)).
- Server-side targeted module writes update tracked collection body revisions when they actually run: collection table writes update body revisions ([`server/fastify/src/repository.ts` lines 726-755](../../../../../server/fastify/src/repository.ts#L726-L755)), and row writes sync the changed row revision ([lines 811-817](../../../../../server/fastify/src/repository.ts#L811-L817)). The body-cache problem for the findings above is that no command reaches these writers, so no server mutation or cache revision can be produced.

## Suggested Fix Direction

Route module add/import paths through the existing bridge helpers or normalize IDs before mutating watched arrays. For module regex/trigger definitions, mirror the character draft path by calling the script-definition bridge normalization/dispatch path instead of relying on watcher pickup for freshly-created ID-less records.
