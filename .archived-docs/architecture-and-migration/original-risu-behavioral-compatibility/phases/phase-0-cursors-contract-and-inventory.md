# Phase 0 — Cursors, Contract, Inventory, And Pilot

Status: Complete
Depends on: none

## Objective

Turn the recorded behavioral sync cursor into a short, trustworthy opening
phase without treating it as a new compatibility baseline. Freeze the source
authorities, import prior decisions and upstream dispositions, ratify the
machine-readable registers, establish baseline reproducibility, and prove the
audit method on recent recurring omission classes.

## Scope

- Compatibility baseline `71c476e9c86263fe907105b011ca4dde0a619d66`.
- Upstream disposition interval `71c476e9c..f3f0242fb`.
- Native Fastify port and compatibility history through planning anchor
  `1933c43ff7b4d35b57b0852013d95f3881a8cb28`.
- Archived 2026-08 compatibility findings/decisions and later upstream-sync
  records as import sources, not automatic current verdicts.
- Inventory, finding, decision, normalization, and verification vocabularies.
- A pilot covering representative losses in preset option persistence,
  translation runtime/profile dispatch, Responses endpoint preservation, and
  portable reroll candidates.

## Required Work

1. Record exact repository/object availability and create a reproducible,
   detached baseline-worktree preparation procedure for
   `/home/codex/risu-baseline-71c476e9c`.
2. Import every upstream unit through the sync cursor with separate fields for
   upstream disposition, native port commit, current owners, and current
   verification state.
3. Import prior individually authorized divergences and unsupported boundaries;
   return ambiguous historical prose to `proposed` rather than inferring sign-off.
4. Ratify JSON schemas and add referential/uniqueness validation for inventory,
   findings, raw mappings, and decisions.
5. Trace the pilot on both reference and current paths, enumerate relevant
   legacy/default/failure variants, and create the first structural or
   differential evidence without pre-judging outcomes.
6. Convert pilot differences to canonical findings or decision requests and
   define exact Phase 1 harness inputs.

## Required Outputs

- Populated initial inventory and imported decision/upstream registers.
- Baseline preparation and smoke-check procedure with failure diagnostics.
- Pilot evidence and canonical mappings for all selected recurrence classes.
- Ratified normalization rules and fixture provenance.
- Exact first Phase 1 slice and first domain-phase slice in `status.md`.

## Exit Criteria

- All pre-Phase-1 gates in `PLAN.md` pass.
- The baseline prerequisite is either present and smoke-tested or represented by
  a reproducible procedure plus an explicit local blocker; Phase 1 still owns
  making the gate routinely executable.
- Every imported upstream unit has both disposition and current-verification
  fields, even when verification remains pending.
- Every historical authority is linked by stable decision ID or explicitly
  marked import/authority pending.
- The pilot produces independently reviewable rows/evidence and no raw report is
  left unmapped.

## Validation

- JSON parse/schema and referential checks.
- Baseline commit/worktree and compatibility-harness smoke commands when
  available.
- Focused tests introduced by the pilot.
- Markdown formatting and `git diff --check`.
