## Notable cases

- L2 is the most substantially reframed finding. The old database-bearing bootstrap and its revisioned body-cache implementation no longer exist. Recovery now reads separate settings, collections, character shells, and inlay catalog resources, with hash substitution for most large bodies. I classified it PARTIAL because recovery still requests the complete resource set rather than only resources changed since the last known revision.
- L5 is deliberately partial. Inline streams avoid the duplicate terminal text, but durable streams keep it because their replay/reattach contract may need a self-contained final result after token frames are lost or evicted.
- L14 is certainly unbounded, but the degree of avoidable transfer is workload-dependent: the current Hypa UI actively loads all summaries for the selected chat. Pagination would still provide hardening for very large histories.
- L16’s bytes remain on the wire, but the field is not dead data: the originating client uses it for own-event detection ([bootstrap.ts:1847](../../src/ts/bootstrap.ts:1847)), and persistence preserves the same behavior after SSE replay. The transfer finding remains technically open, while removing it would require a different own-echo protocol.
- No finding was classified OBSOLETE. H1, L1, and L2 had their original bootstrap framing replaced, but each still has a clear current behavioral equivalent.
